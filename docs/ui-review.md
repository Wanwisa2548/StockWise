# ผลทบทวนฟีเจอร์และข้อความ StockWise

เกณฑ์: แต่ละหน้ามีหน้าที่ชัดเจน คำแนะนำหนึ่งรายการมีจุดดำเนินการหลักจุดเดียว ข้อมูลขั้นสูงยังตรวจสอบได้ และการทดลองไม่เปลี่ยนค่าของงานจริง

## สิ่งที่ตัดออก

| ส่วนเดิม | เหตุผล | ทางเลือกที่เหลือ |
|---|---|---|
| หน้าสรุปผลและโค้ดคัดลอก 255 บรรทัด | ซ้ำภาพรวม พยากรณ์ แผนสั่งซื้อ ล็อต ยอดขาย และจัดกลุ่ม อีกทั้งมีตัวควบคุมค่าเดียวกันหลายจุด | ภาพรวมร้าน + หน้ารายละเอียดแต่ละงาน ลิงก์เก่า #summary กลับภาพรวม |
| กราฟสต็อก 30 วันและ Calc.simulateStock | ใช้ยอดคงที่ ไม่คิดหมดอายุ ต่างจากแบบจำลองที่คิดล็อต จึงทำให้ตีความผลสองหน้าปะปน | เปรียบเทียบแผนสต็อกซึ่งคิดยอดย้อนหลัง Lead Time และหมดอายุ |
| รายการแนะนำโปรโมชั่นซ้ำตารางล็อต | มีปุ่มตั้งโปรสองแห่งสำหรับล็อตเดียวกัน | แสดงเหตุผล ราคา เวลา และปุ่มในตารางล็อตเดียว |
| สถานะซ้ำวันสั่งและคอลัมน์สูตรในตารางสั่งซื้อ | ตาราง 10 คอลัมน์อ่านยาก คำว่า EOQ ไม่ใช่จำนวนที่สั่งจริงเสมอ | 6 คอลัมน์หลัก เปิดเหตุผลเพื่อดูโมเดล EOQ/ROP/Safety Stock |
| ชื่อสินค้าแสดงสองครั้งในสินค้าขายดี | ข้อมูลชุดนี้ใช้ชื่อเดียวกันทั้งสองบรรทัด | ชื่อหนึ่งบรรทัด ตามด้วยจำนวนขาย |
| หัวข้อภาษาอังกฤษตกแต่งซ้ำหัวข้อไทย คำ Workspace และอวาตาร์บัญชีสมมติ | เพิ่มข้อความและภาพที่ดูคล้ายมีระบบบัญชี ทั้งที่ไม่มีฟังก์ชันนั้น | ชื่อหน้าไทยที่ตรงกับเมนู และป้ายแหล่งข้อมูล |
| SQL ตัวอย่างในหน้ารายการขาย | ไม่ช่วยผู้ดูแลร้านตัดสินใจ | ข้อความสรุปที่มาของยอดรายวัน ส่วนสูตรคงในเอกสาร |

## สิ่งที่ย้ายเป็นรายละเอียดเปิดดูได้

- ภาพรวม: การคำนวณรายสินค้า EOQ ช่วงคาดการณ์ ใบแทนค่า และการส่งออกผลคำนวณ
- พยากรณ์: ปรับโมเดลเอง ตัวชี้วัดย้อนหลังทั้งช่วง ตารางเปรียบเทียบ ตารางอนาคต และผลที่บันทึก
- ล็อต: โปรโมชั่นที่บันทึกและกฎส่วนลด
- ยอดขาย: ตัวอย่างรวมยอดรายวันและรายการขายล่าสุด
- จัดกลุ่ม: กราฟ Elbow วิธีคำนวณและผลที่บันทึก
- เปรียบเทียบแผน: ตัวชี้วัดหลัก 5 รายการก่อน รายละเอียดสินค้า/ต้นทุน เหตุการณ์รายวัน และข้อจำกัดเปิดดูได้

รายละเอียดเหล่านี้จำเป็นต่อการอธิบาย DSS จึงยังเก็บสูตรและหลักฐานไว้ คงโมเดล 9 ตัวเลือก EOQ/ROP FEFO K-means การทดสอบโมเดล การเปรียบเทียบนโยบาย และสไลด์ 9 หน้า

## พฤติกรรมที่แก้เพื่อลดความสับสน

1. ปรับ MA/ES มีผลกับสินค้าที่เลือกเท่านั้น ไม่เปลี่ยนค่าเริ่มต้นของสินค้าอื่น
2. เมื่อใช้ Seasonal naïve/Naïve ตัวปรับ MA/ES ไม่แสดงว่าเป็นวิธีที่ใช้อยู่ ต้องเลือก MA หรือ ES ก่อนปรับ
3. ปุ่มโมเดลที่แนะนำแจ้งว่าใช้อยู่และปิดเมื่อเลือกตรงกันแล้ว
4. ค่าทดลอง Service Level/อัตราเก็บรักษาเก็บแยกรายสินค้า ไม่เปลี่ยนแผนสั่งซื้อ สไลด์/CSV ใช้ค่าทดลองตรงกับผลที่แสดง
5. ข้อมูลยอดขายศูนย์แสดง — สำหรับชั่วโมงขายดี/เวลาโปรที่หาไม่ได้ ไม่แสดง 00:00 ให้เข้าใจว่าเป็นเวลาแนะนำ
6. หน้าใกล้หมดอายุเริ่มจากล็อตที่ต้องจัดการ เปิดดูล็อตอื่นได้ด้วยตัวกรอง และไม่เรียกทุกล็อตเสี่ยงว่า “ควรจัดโปร” เมื่อยังไม่เข้าเกณฑ์ส่วนลด

## คำเรียกหลัก

| คำในเมนู | ใช้เพื่อ |
|---|---|
| ภาพรวมร้าน | ยอดขายและงานที่ควรจัดการ |
| วิเคราะห์ยอดขาย | ช่วงเวลาขายดี |
| พยากรณ์ยอดขาย | เลือกและตรวจโมเดล |
| แผนสั่งซื้อ | ตรวจจำนวน/วันสั่งและสร้างใบสั่ง |
| สินค้าใกล้หมดอายุ | ดูล็อตและตั้งโปรโมชั่น |
| สินค้าและสต็อก | แก้ข้อมูลต้นทาง |
| จัดกลุ่มสินค้า | แนวทางดูแลรายกลุ่ม |
| เปรียบเทียบแผนสต็อก | ทดลองนโยบายแยกจากแผนจริง |
| สไลด์นำเสนอ | อธิบายโมเดลและผลทดลอง |

การใช้คำ Confidence, RMSE, EOQ และชื่ออัลกอริทึมคงไว้เฉพาะจุดที่ใช้วิเคราะห์/อธิบาย ไม่เรียก Confidence ว่าเปอร์เซ็นต์ความแม่นยำ หรือผลจำลองว่าผลประหยัดจริง
