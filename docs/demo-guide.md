# เตรียมนำเสนอและ Demo

## ก่อนนำเสนอ

1. `npm start` กับฐาน Demo แยกจากข้อมูลใช้งาน ตรวจ VPN/SQL และ SIM_TODAY หากไม่มีฐานใช้ `npm run demo` มีป้ายจำลองและปิดการบันทึก
2. เปิดทุกหน้าเช็กข้อมูล ไม่รัน seed.js บนฐานที่นำเข้าข้อมูลแล้ว
3. เลือกสินค้าในพยากรณ์ ตรวจ validation/test และกดใช้โมเดล ไม่จำเป็นว่าโมเดลซับซ้อนต้องชนะ
4. ตั้งตัวเทียบในเปรียบเทียบแผนสต็อก จดต้นทุน/อายุ/Lead Time/penalty/สต็อกเริ่ม อย่าปรับเพียงเพื่อให้ DSS ดูดี
5. เปิดสไลด์นำเสนอ เลือกสินค้า บันทึก HTML ออฟไลน์หรือพิมพ์เป็น PDF ผ่านเบราว์เซอร์ สไลด์ดึงตัวเลขที่โหลด
6. ส่งออก CSV ผลโมเดล/นโยบายและใบคำนวณ เก็บคู่สไลด์ ถ่ายวิดีโอสำรองเมื่อเครือข่ายไม่แน่นอน

## บทนำ

“StockWise ช่วยผู้ดูแลสต็อกร้านเบเกอรี่ตัดสินใจว่าจะเตรียมและสั่งเท่าไร เมื่อไร และจัดการล็อตใกล้หมดอายุอย่างไร ใช้ยอดขายย้อนหลังร่วมกับโมเดลและต้นทุน ผู้ใช้ตรวจเหตุผล ปรับสมมติฐาน และเลือกดำเนินการเอง”

## Demo 5–7 นาที

1. **ภาพรวม:** บอกวันวางแผน ช่วงข้อมูล สินค้าที่เลือก และข้อมูลประกอบที่กำหนดแยกจากยอดขาย
2. **พยากรณ์:** เปิด “ดูผลเปรียบเทียบและวิธีทดสอบ” แสดงวันฝึก/validation/test ทุกวิธีทดสอบวันเดียวกัน อธิบาย baseline เลือกจาก validation ตรวจ Test แยก แล้วกดใช้โมเดล
3. **แผนสั่งซื้อ:** เปิดเหตุผล ชี้สต็อกใช้ได้เทียบ ROP ทำไมจำนวนต่ำกว่า EOQ เปลี่ยน Service Level ดูผลที่ Safety Stock/ROP เปิดภาพรวม → ตรวจผลคำนวณรายสินค้า → ดูวิธีคำนวณ
4. **เลือกดำเนินการ:** ใช้ฐาน Demo จริงกดสั่ง ดูใบสั่งรอรับและป้องกันสั่งซ้ำ การรับของเพิ่มล็อตเป็นการสาธิต อย่าอ้างรับก่อนวันจริงเป็นข้อมูลจริง โหมดจำลองปิดปุ่มบันทึก
5. **ล็อต:** อธิบาย FEFO/ส่วนลด ตรวจราคากับต้นทุนก่อนตั้งโปร ไม่อ้างยอดเพิ่มตามเปอร์เซ็นต์ส่วนลด
6. **ประเมินผล:** เทียบขาดขาย/หมดอายุ/สต็อก/ต้นทุน เปิดสมมติฐานและรายวัน อธิบายผลที่แย่กว่าได้ ส่งออก CSV
7. **สไลด์:** สรุป 9 หน้า ข้อจำกัดและแผนยืนยันกับข้อมูลจริง

## คำตอบเมื่ออาจารย์ถาม

**ทำไมเป็น DSS?** เชื่อมข้อมูล/โมเดลกับคำแนะนำจำนวน เวลาสั่ง และล็อตที่ต้องจัดการ ผู้ใช้เลือกทางเลือกเอง

**สร้างโมเดลอย่างไร?** เตรียมรายวัน สร้างตัวเทียบ กำหนด MA/ES เลือก validation ตามเวลา ประเมิน Test ที่ไม่ใช้เลือกพารามิเตอร์

**แม่นเท่าไร?** แสดง MAE/RMSE/MAPE สินค้านั้นบน Test พร้อมวัน/จำนวนตัวอย่าง ไม่มี accuracy เดียวใช้ทุกสินค้า Confidence 95% ไม่ใช่แม่น 95%

**ลดของเสียจริงหรือยัง?** เป็นผลจำลองภายใต้สมมติฐาน ต้องวัดกับร้าน/ข้อมูลใหม่ ไม่ใช้มูลค่าเสี่ยงแทนยอดประหยัด

**ทำไมใช้ EOQ กับขนมอายุสั้น?** ใช้เศรษฐศาสตร์เป็นจุดตั้งต้นแล้วจำกัดอายุ แสดงข้อจำกัด โมเดลยังไม่ใช่ปริมาณอบที่เหมาะที่สุดสำหรับของเสียง่าย

**K-means accuracy?** ไม่มีป้ายจริงให้วัด accuracy ใช้ SSE/Elbow/Silhouette ประกอบความหมายธุรกิจ นโยบายเป็นกฎแนะนำ
